A focus widget that refuses to interrupt you.

DODO Timer is a desktop tool built end-to-end by a UX designer with Claude as engineering partner. The first thing I shipped that runs on someone else's machine — and proof that taste, not technical depth, is the real bottleneck.

01 Spark
The trigger

It started with a LinkedIn scroll.

Someone posted a concept for a tiny focus widget. I stopped scrolling — I knew the problem, because I'd been losing two-hour blocks to deep work with nothing to pull me back.

Existing timers all asked the same wrong question first: how long? I was tired of answering it. The hours never matched what the work actually needed. And every Pomodoro app I'd tried treated my attention like a budget to spend — when what I actually needed was a witness.

I closed LinkedIn and opened a terminal.
02 Insight
Reframe

The value isn't the timing. It's the naming.

Every other timer asks how long? first. DODO asks what are you working on? One field. One commitment. The clock is incidental to the ritual.

This was the call that changed everything. It cut the feature list in half. It made duration optional, made distraction blocking redundant, and made the rest of the design self-evident — if naming the task is the whole product, then the UI exists to honour that one moment of commitment, then disappear.

The real product is the naming, not the clock.
03 Modes
System

Three states, one principle.

The attention the timer deserves changes across a session. The tool should, too.

Setup demands focus. Widget mode lets you check in. Pill mode is where it lives 90% of the time — small enough to ignore, present enough to remember. Each mode is the same product at a different volume.

04 The Pivot
Aesthetic call

From anime to Dieter Rams.

A focus tool that visually interrupts you is a contradiction. The first version had a dark JRPG aesthetic — fun, but wrong. It was a tool that wanted attention, in a category that should ask for none.

The rewrite wasn't a reskin — it was a forcing function that deleted half my features. If the visual language is restraint, then any feature that wants attention has to justify itself loudly, and most couldn't.

05 Product Rationale
Decisions

Three calls that mattered.

Every product is the sum of the things it refused to do. These are the three refusals that make DODO what it is.

01

Name the task, not the duration

Duration is optional. Most users skip it. The naming is the value — it's the moment of commitment that the rest of the session is held against. Removing the duration prompt felt risky. It wasn't.

02

Pill is the product, widget is the admin

I built the widget first, then realised the pill is the product. Always-on-top only works if the tool is tiny enough to ignore. The widget became the configuration screen for the pill — not the other way around.

03

Corner-snap, not free drag

Four corner positions, not infinite placement. Fewer choices, better outcomes. A classic design call — only this time I had to implement it myself, which made the call easier, not harder. Constraints look better in code.

06 Claude as Partner
Process

Not a tool. A collaborator.

First thing I've shipped that runs on someone else's machine. Claude didn't write the code for me — it worked with me, the way a good engineering partner would.

Claude led

Tauri setup, Rust window config, GitHub Actions cross-platform builds. The infrastructure I had no context on — and didn't need to learn from scratch to ship.

I led

Every product decision. What stays, what gets cut, what the thing is. Taste stayed the bottleneck — which is how it should be. The partnership only works if the human is still the editor.

The pattern that worked: I'd describe the feeling I wanted — "this should sit on Dieter Rams' desk, not in a video game." Claude translated that into implementation. I reviewed, pushed back, iterated. The loop tightened over weeks; by the end, I was shipping changes in minutes, not days.

Claude didn't turn me into an engineer. It removed the excuse not to ship.

08 What This Was
Reflection

A timer. Also a case against the idea that designers can't ship.

DODO is small. The thing it proved is not.

Eight years of designing for other people to build. One product I designed and built end-to-end. The gap between Figma and production isn't technical — it's psychological. DODO is the proof I needed that I can close it.

Next: session history, streaks, one-click restart. Then a public launch. The tool is small on purpose; the discipline behind it is the part I'm carrying into everything else.
